# 2026-010-02.java.event-timing-framework

Public Java framework for reusable event timing and time-registration applications.

## Current scope

This repository is the public implementation repository for **SI-01 — Headless Timing Application**. The current bootstrap increment establishes the Java/Maven component boundaries and proves the shared build/test toolchain. It intentionally does not implement RFID, CAN, display, backoffice or timing-domain behaviour yet.

## Module structure

```text
timing-api       public contracts and shared cross-module models
timing-core      application/domain behaviour
timing-runtime   hosting, routing, lifecycle and execution infrastructure
timing-adapters  public/default infrastructure adapters
timing-testkit   reusable public test support
timing-app       small executable/composition root
```

Initial dependency direction:

```text
timing-api
    ^
    |
timing-core
    ^
    |
timing-runtime
    ^
    |
timing-app

 timing-adapters -> timing-api
 timing-testkit  -> timing-api
```

The component structure follows the working design in the meta repository: `2026-010-01.meta.event-timing-software/docs/31-01-SDD-03-java-component-design.md`.

## Toolchain baseline

```text
Java              Eclipse Temurin 8u504-b01 (`8.0.504+1` in CI)
Java source/API    Java SE 8
Maven              3.9.16
Maven Wrapper      3.3.4
```

Build on Linux/macOS:

```bash
./mvnw verify
```

Build on Windows:

```powershell
.\mvnw.cmd verify
```

Run the bootstrap application after a reactor build:

```bash
java -jar timing-app/target/timing-app-0.1.0-SNAPSHOT.jar
```

Expected bootstrap output:

```text
event-timing-framework bootstrap OK
```

## Reusable CI

This repository is the first real external consumer of `brainboxemb/tool.java-project`. CI calls the reusable workflow pinned to an immutable toolchain commit rather than the moving `main` branch.

The CI proof includes:

- Linux canonical reactor build/test and artifact production;
- Windows reactor build/test;
- download and execution on Windows of the exact `timing-app` JAR produced by Linux;
- build/test provenance generated by the reusable toolchain.

Docker is not required for the normal Java build/unit-test path. It may be introduced later for integration tests that need real external services.

## Development workflow

Changes use issue → feature branch → draft PR → implementation/test/evidence → review → merge.

Keep real deployment identities, proprietary protocols, credentials, encryption keys and production mappings out of this public repository.
